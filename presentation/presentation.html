🔴 Header (Vermelho)

Metadados: tipo de token e algoritmo de assinatura (ex: HS256, RS256).

🟣 Payload (Rosa)

Claims (dados do usuário: id, role, exp). Legível por qualquer pessoa!

🔵 Assinatura (Azul)

Garante integridade. Se a chave for fraca (ex: "secret123"), pode ser quebrada em segundos!

// VULNERABILIDADE 1 (OWASP API5:2023)

BFLA: Broken Function Level Authorization

A rota checa se você está logado, mas esquece de checar seu papel (Role).

❌ Código Vulnerável

Apenas checa login. Cliente vira Admin!

// Rota de métricas da empresa
app.get("/api/v1/admin/financials", 
  authenticate, // Só checou se tem token!
  (req, res) => {
    res.json(db.getFinancialMetrics());
});

✅ Código Corrigido

RBAC: Middleware exige papel explícito.

// Protegido por Role
app.get("/api/v2/admin/financials", 
  authenticate,
  requireRole("ADMIN"), // 403 se for CUSTOMER
  (req, res) => {
    res.json(db.getFinancialMetrics());
});
// VULNERABILIDADE 2 (OWASP API1:2023)

BOLA: Broken Object Level Authorization

O #1 da OWASP API Top 10! A Maria altera o preço do MacBook do João para R$ 1,00.

❌ Código Vulnerável

Atualiza o ID da URL sem checar quem é o dono.

app.put("/api/v1/products/:id/price", (req, res) => {
  // Confia cegamente no ID do parâmetro!
  Product.update({ price: req.body.newPrice }, 
    { where: { id: req.params.id } });
  res.json({ success: true });
});

✅ Código Corrigido (Ownership Check)

Validação estrita de propriedade do recurso.

app.put("/api/v2/products/:id/price", (req, res) => {
  const product = Product.findById(req.params.id);
  if (product.sellerId !== req.user.id) {
    return res.status(403).json({ error: "Acesso Negado" });
  }
  product.updatePrice(req.body.newPrice);
});

// LIÇÕES PARA A CARREIRA

3 Mandamentos da Segurança em APIs

O que vocês, futuros desenvolvedores e arquitetos de software, devem levar hoje:

1. Token ≠ Permissão

Saber quem é o usuário é só a metade da segurança. Saber o que ele tem direito de acessar é a outra metade.

2. Valide o Dono Sempre

Nunca faça update ou delete baseado apenas no `ID` vindo na URL. Sempre amarre `WHERE id = ? AND owner_id = ?`.

3. Segredo JWT Forte

Use chaves aleatórias de 256 bits geradas criptograficamente e valide o algoritmo no backend.
